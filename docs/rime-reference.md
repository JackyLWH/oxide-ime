# RIME 長文與候選測試筆記

以下是舊 RIME 維護工作保存的結論，適用於當時測試的小狼毫 0.17.4／librime 1.13.1。現有 Oxide IME 的回歸測試另行驗證長文及多行文字可透過 Windows TSF 完整上屏。

- 先前重現小狼毫的候選及上屏回應填滿 65,536 位元組並缺少結束標記。核心候選仍然存在，畫面未更新與上屏只收到部分文字都可由前端通訊截斷解釋。
- 用合成文字在隔離核心測試 200,000 字的候選時，核心能完整產生、選取並回傳全文。帶 Lua 的轉換候選生成約需 174–196 毫秒，直接字典候選的四鍵查詢約需 1.2 毫秒。測試未量度前台應用實際插入文字的耗時。
- 曾在部分應用見到多行輸出的行末字元移位，而核心選字回傳的全文及換行正確。相似個案可參考 [小狼毫問題 #1933](https://github.com/rime/weasel/issues/1933)。舊測試未定位應用接收端的根本原因。

Oxide IME 的候選窗只用預覽文字。普通宿主透過 TSF 一次提交完整候選。沙盒字庫先回傳預覽，選字時透過受限於本機的字庫服務取回原文，再由宿主的 TSF 一次提交。舊有測試剪貼簿、特定私人詞條、快照或前端探針無需保留在現用專案。
